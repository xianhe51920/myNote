## 4. Assumptions & Decisions

| 假设/决策 | 理由 |
| :--- | :--- |
| 一章一个处理轮次（共 4 轮），每轮内一次性 Read 该章所有 PNG | 控制单次输出体量，便于失败时回滚到上章 |
| 章节 H2 标题 = 子文件夹名去掉前导序号 | SOP 第 1.3 节规定 |
| 第零章 H2 写为 `## 第零章 导学部分` | 子文件夹名 `0.第零章 导学部分` 去前缀后即此 |
| 第三章 H2 写为 `## 第三章 Java 基础语法`（小写 java） | 与 PPT 原章节名一致（之前会话的写法） |
| 第三章二级目录 `03.第三章：Java基础语法` 不影响 H2 取名 | 真正的 H2 由 `3.第三章 JAVA基础语法` 决定 |
| 不在 md 表格中使用 HTML 颜色 | SOP 第 163 行明确禁用 |
| 不在 md 中写「整理完成」等元信息 | SOP 第 154 节禁用项 |
| 跳过明显的目录页、装饰页、纯标题页 | SOP 第 6.5 节 |
| 不重命名 / 移动 PNG 文件 | SOP 第 162 行 |

3. 检查没有触发任何禁用项（表格无颜色、无元信息行、无图片引用、无来源行）
4. mermaid 代码块配对（` ```mermaid ` 起止齐全）
5. 简短汇报：本次整理 N 张 → 第 X 章 → yyy.md（H2 + K 个 H3）

6. 写入顶部目录区（4 条 H2 锚点链接）

## 6. Risk & Mitigation

| 风险 | 缓解 |
| :--- | :--- |
| 108 张图一次 Read 后上下文过长 | 分 4 轮执行；每章完成后用 `Read` 验证后即清空阅读上下文 |
| 第三章 47 张内容多，H2 写入体积大 | 单章一次性 Edit 写入；如超长则拆为 H2+H3-1..H3-2.. 多次 Edit |
| PNG 读不出或模糊 | 跳过该张、汇报中说明跳过的位置 |
| 表格与 mermaid 语法有误 | 每章验证步骤第 3/4 条检查 |
| 用户对某一章整理结果不满意 | 用户可在下一轮指示「重做第 X 章」，按 SOP 6.2 节追加模式处理 |
